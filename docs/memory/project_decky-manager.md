## 1. Goal & scope

Ships: (a) install / repair / uninstall **Decky Loader** on the box from the phone; (b) list installed plugins (name, folder, version, author, root flag, disabled/hidden/frozen, backend running, update available); update / uninstall / reload a plugin; (c) browse + search the official store (box-fetched, box-cached, box-proxied icons) and install a plugin; (d) KI-004 recovery made **explicit**: a stopped loader is surfaced as a state with the existing `restart-decky` action and Repair offered — never a silent restart inside another op; (e) one box-side opt-in `couchside allow-decky on|off|status`, also *offered* once by an interactive install.sh run; (f) Utilities tenant `decky` (Engine B, project_utilities-menu.md:18-19 names "Decky install/repair" as a planned tenant) plus one dedicated screen `app/app/decky.tsx` and a Setup card next to `SystemUpdatesCard`.

Does not ship (follow-ups, §17): enable/disable/hide/freeze; choosing an older store version (the DOWNGRADE case is *presented* honestly when the box is ahead of the store, never silent); "update all" / "update everything" wiring; **loader self-update through Decky's own updater** (`updater/do_update` — dropped, see §11); prerelease loader channel; a root-side zip extractor (deliberately never); custom/testing stores; anything needing a CEF tab (`execute_in_tab`, `get_tab_id` — they hang forever without Steam, verified); marker-gating the helper's existing `update.flatpak`/`update.os` verbs (moved to follow-up F8: it couples to a file project_privileged-helper.md §4 phase 2 plans to stop writing, and the agent never calls those verbs today — `flatpak_update()` :2198 / `os_update_apply()` :2375 shell `sudo -n <wrapper>` directly); Windows/macOS agents (every route 404s there).

**The material security fact, stated up front** (it drives §5's copy and KI-070): Decky Loader runs as root out of the desktop user's home (`ExecStart=~/homebrew/services/PluginLoader`, `User=root`), hands its API token to any local process (`GET /auth/token` is unauthenticated, no Origin/Host checks), and its own updater `chmod 777`s the binary. On a Decky box, anyone who can act as the desktop user — including a paired phone through the virtual gamepad — is root-equivalent **with or without** anything Couchside adds; the standing `systemctl restart plugin_loader` grant is a root-exec primitive on such a box. This is Decky's design; Couchside cannot wall it off, only refuse to make it worse (root-owned `services/`, no `777`, no self-update route) and say so plainly.

## 2. Architecture

| Process | Runs as | Does | Never does |
|---|---|---|---|
| Phone | — | probes `/api/decky/loader` (404 → whole surface hidden), renders states, searches the box-served list locally | contacts deckbrew / GitHub / the CDN |
| Agent `couchsided.py` | desktop user | loader state (memoised); fs plugin listing; store fetch+cache+normalise (background thread); icon proxy (no redirects); its own bounded stdlib WS client to `127.0.0.1:1337` (loader identity checked via `/proc/net/tcp` uid); one `_decky_busy()` mutex across loader ops + plugin jobs; disk-persisted job record with resume; op read-back correlated to the request; actions resync; mock | root work, zip bytes, paths built from client strings, silent loader restarts |
| Helper `couchside-helper.py` 1.1.0 | root | verb `decky.loader {install\|uninstall}` → `systemctl start --no-block couchside-decky-loader@<mode>.service` | run the wrapper as its own child (ProtectHome=yes would hide `/home`; Accept=no would block every other verb for minutes) |
| Unit template `couchside-decky-loader@.service` | root, PID 1 | `Type=oneshot`, `ConditionPathExists=/etc/couchside/allow-decky`, `TimeoutStartSec=900`, `ExecStart=/etc/couchside/couchside-decky-loader %i` | — |
| Wrapper `/etc/couchside/couchside-decky-loader` | root | the ONLY new root logic: refuse symlinked user trees, fetch stable `PluginLoader` with bounded curl, stage, swap `services/` with rollback, write the unit, enable, verify the loader actually answers; or remove | forward args, read `SUDO_USER`/`HOME`, touch `plugins/`, follow a symlink under `$HOME` as root, `chown` anything under `$HOME` to the user |
| Decky Loader (upstream, root) | root | downloads the plugin zip, **sha256-checks it against the hash we pass**, extracts, chowns, starts/stops plugin backends | — |

Both privilege paths converge on the same unit → same wrapper → same `/run/couchside/decky-loader.{lock,log,result}` → one status reader. The wrapper never runs inside the agent's or the helper's cgroup, so an agent restart mid-install cannot kill it and the helper's sandbox is irrelevant to it; PID 1 kills a hung run at 900 s and the EXIT trap records `failed`.

## 3. The allowlist model (CLAUDE.md §3) — every client-influenced value

| Value | Enters via | Lookup / validation | Failure |
|---|---|---|---|

| loader op | `?op=` | **missing** `?op=` → 200 `{ok:false, error:"Update the Couchside app to manage Decky Loader"}` (an old app's UtilitiesSection shows that string; never a 400 dead button); present → `op in _DECKY_LOADER_OPS = ("install","uninstall")`; dispatch via `_DECKY_UNITS = {"install": "couchside-decky-loader@install.service", "uninstall": "couchside-decky-loader@uninstall.service"}` — the argv element is the dict *value*, never the query string | 400 |
| plugin op | fixed route literals `/api/decky/plugins/uninstall`, `/reload` (dict `_DECKY_PLUGIN_OPS` → WS route constant) | literal match | 404 |
| plugin `name` | JSON body | `isinstance(str)`, 1–64 chars, `.isprintable()`; then **membership** in `_decky_plugins_on_disk()` — the dict keyed by each folder's `plugin.json["name"]` (§7 names the two helpers: `_decky_loader_installed()` is the bool, `_decky_plugins_on_disk()` is the dict — never one name for both). The string handed to Decky is `plugins[name]["name"]`, the dict's own key. `_decky_protected(name)` = `unicodedata.normalize("NFKC", name).strip() in _DECKY_PROTECTED` (`frozenset({"Couchside"})`) → 409 for every op; the fs listing marks any folder whose normalised name collides as `protected:true` too | 404, no socket opened |
| store `id` | JSON body of `/plugins/install`; path segment of `/store/icon/<id>` | body: `isinstance(id, int) and not isinstance(id, bool) and 0 < id < 10**9`; path segment: `re.fullmatch(r"[0-9]{1,9}", seg)` then `int()` (never `str.isdigit()` — `'²'.isdigit()` is True and `int('²')` raises); then key of `_DECKY_STORE["by_id"]` (the box's own last fetch). `versions[0]` is always used; its `hash` must `re.fullmatch(r"[0-9a-f]{64}")` else 422 `no verifiable hash` (an empty hash makes Decky skip its sha256 gate, verified). **The resolved entry's normalised `name` is checked against `_DECKY_PROTECTED` → 409 before any socket** (a store entry named `Couchside`/homoglyph would otherwise make Decky `uninstall_plugin("Couchside")` first). Artifact URL = `_DECKY_CDN + hash + ".zip"` built by the agent; `name`/`version`/`install_type` come from the entry + agent comparison, never the body | 404; 409 protected; cold cache → 503 `store_unavailable`, no socket |
| image bytes | icon route | `image_url` of the looked-up entry; `urlparse` scheme `https` and hostname exactly `cdn.tzatzikiweeb.moe`; fetched with `_DECKY_NO_REDIRECT_OPENER` (an `HTTPRedirectHandler` whose `redirect_request` returns `None` — any 3xx is a failure, so a CDN 302 to `http://192.168.1.1/` is never followed); ≤1 MiB; `_decky_sniff_image` (= `_sniff_image` :14476 plus AVIF `data[4:12] == b"ftypavif"`) must return jpeg/png/webp/gif/avif; cached at `realpath(_DECKY_ICON_DIR)/<int id>` (path from the int, never the request) | 404 |
| loader auth token | `GET http://127.0.0.1:1337/auth/token` | only after `_decky_loader_is_root()` (§10: `/proc/net/tcp` row for `0100007F:0539` in LISTEN with uid 0; unreadable/absent/non-root → `loader_down`); token `re.fullmatch(r"[0-9a-f-]{36}")` before it is placed in the handshake request line; never logged or returned | op fails `loader_down` |
| WS routes | agent constants | `_DeckyWS.call` raises unless `route in _DECKY_WS_ROUTES` (frozenset, §10) | RuntimeError before any send |
| `?n=` on log | query | `int` clamped 1..400 | — |
| store `?q`, `sort`, `version`, `channel`, `hash` | — | **do not exist** in v1 | — |

Paths: all roots are module constants (`_DECKY_UNIT`, `_DECKY_HOMEBREW = expanduser("~/homebrew")`, `_DECKY_PLUGINS_DIR`, `_DECKY_LOADER_BIN`, `_DECKY_SETTINGS`, `_DECKY_MARKER`, `_DECKY_WRAPPER`, `_DECKY_UNIT_TMPL`, `_DECKY_RUN = "/run/couchside"`, `_DECKY_ICON_DIR`, `_DECKY_JOB_FILE = ~/.cache/couchside/decky-job.json`, `_DECKY_STORE_URL`, `_DECKY_CDN`) so tests repoint them. **Containment compares resolved against resolved**: `root = os.path.realpath(_DECKY_PLUGINS_DIR)` computed per call, a folder is listed only if `os.path.realpath(join(root, d)).startswith(root + os.sep)` and it is a directory containing `plugin.json` (same rule for `_DECKY_ICON_DIR`; precedent `_drop_dir()` :1778). This is what makes a symlinked `~/homebrew` (SD-card relocation) and Bazzite's `/home → /var/home` list correctly instead of returning a confident empty list. `plugin.json`/`package.json` reads are capped at 64 KiB; a parse failure or over-cap file marks the entry `unreadable` (counted, omitted). Folder names come only from `listdir`.

Store data is normalised **by rejection** (an entry is dropped, never repaired, on any violation): `id` int-not-bool in `(0, 10**9)`; `name` 1–64 printable str; `author` str ≤64 printable; `description` str, cut at 400 chars (the one trim, since it is display-only); `tags` list of ≤10 str each 1–24 printable; `downloads` int ≥0; `created`/`updated` str ≤32; `versions` non-empty list capped at 5, each `{name: str ≤32, hash: 64-hex, created: str ≤32}`; `image_url` kept only under the host+scheme rule above, else `null` (a bad image never drops a good entry — that is the one field normalised to null rather than rejecting, because the loader treats it as optional too). `has_icon` = `image_url` non-null; every kept type is sniffable, so the tile is never advertised-then-404.

Degrade closed: no Steam root → `/api/decky/*` 404 and **no `decky` row in `/api/utilities`** (like `_inject_decky_action` :956 hides itself; no client ever sees `unsupported`); wrapper or unit template missing → `installer_ready:false`, loader ops answer `{ok:false, needs_installer:true}` and spawn nothing; helper present but predating the verb → `helper_outdated:true`, Install hidden, copy names the helper; marker absent → 403 `needs_optin` on every marker-gated route, nothing spawned, no socket; `_decky_busy()` → 409 `{busy:true, what:"loader_op"|"plugin_job"}`; loader stopped → 409 `loader_stopped` with the restart action named, no auto-restart; loader not root / token silent → 503 `loader_down, repair:true`; store unreachable → `available:false` or last copy with `stale:true`, never a guessed "no updates"; unreadable plugin dir → entry omitted + `unreadable:n`; `loader.json` unparsable → `flags_available:false`, flags `null`, `update:null` (unknown, never "enabled"); helper refusal → surfaced as final, never retried via sudo; helper socket present but silent → `helper_unreachable, retry:true`, no sudo; WS closed mid-call → outcome `unknown` and the disk read-back decides, never `failed` from the close alone; completion always read back from disk **and correlated to this request**, never assumed.

## 4. Privilege path

### 4.1 Wrapper (heredoc `DECKYWRAP` in a new install.sh section **(f1c)** right after (f1b) :1241-1307, next to the OS wrapper; baked with `sed 's|__USER__|…|;s|__HOME__|…|'` **only after install.sh has refused a `$HOME`/`$USER_NAME` not matching `^[A-Za-z0-9/._-]+$`** (reject, don't sanitise — `&`, `|`, `\` would corrupt every `sed`-substituted line of the unit); `sudo install -m 0755 -o root -g root … /etc/couchside/couchside-decky-loader`; installed ALWAYS, inert until opt-in, like the flatpak wrapper)

```bash
#!/usr/bin/env bash
# couchside-decky-loader install|uninstall — FIXED procedure run as root by
# couchside-decky-loader@.service. The mode is the only input, validated to
# exactly install|uninstall and never forwarded. Target user/home are BAKED.
# RULE: root never follows a path under the user's home. Every write under $H
# is done AS THE USER (runuser) or into the root-owned services/ dir via
# install(1) (which unlinks its destination first); nothing is chown'ed to $U.
set -euo pipefail
U="__USER__"; H="__HOME__"; HB="$H/homebrew"
UNIT=/etc/systemd/system/plugin_loader.service; MARK=/etc/couchside/allow-decky
RUN=/run/couchside; LOCK=$RUN/decky-loader.lock; LOG=$RUN/decky-loader.log; RES=$RUN/decky-loader.result
CURL=(curl -fsS --proto '=https' --proto-redir '=https' --connect-timeout 20 --max-time 300 --retry 2 -A couchside-decky-loader)
[ "$#" -eq 1 ] || { echo "usage: couchside-decky-loader install|uninstall" >&2; exit 2; }
case "$1" in install|uninstall) mode=$1 ;; *) echo "mode must be install or uninstall" >&2; exit 2 ;; esac
[ "$(id -u)" -eq 0 ] || { echo "must run as root" >&2; exit 2; }
install -d -m 0755 "$RUN"; exec 9>>"$LOCK"; chmod 0644 "$LOCK"
flock -w 15 9 || exit 75                    # bounded wait: a poll's LOCK_SH can no longer fail an op; a REAL holder -> touch NOTHING (its result is theirs)
TAG=""; TMP=""; PREV=""
res(){ printf '{"mode":"%s","state":"%s","ok":%s,"tag":"%s","at":%s}\n' "$mode" "$1" "$2" "$TAG" "$(date +%s)" >"$RES.tmp"; chmod 0644 "$RES.tmp"; mv -f "$RES.tmp" "$RES"; }
[ -f "$MARK" ] || { res refused false; echo "decky management not enabled (couchside allow-decky on)" >&2; exit 77; }
res running false                           # FIRST act under the lock, before any redirect or work
exec >"$LOG" 2>&1
rollback(){ if [ -n "$PREV" ] && [ -d "$PREV" ]; then rm -rf "$HB/services"; mv "$PREV" "$HB/services"; systemctl daemon-reload; systemctl enable --now plugin_loader 2>/dev/null || true; echo "rolled back to previous services/"; fi; }
trap 'rc=$?; if [ $rc -eq 0 ]; then res done true; else rollback; journalctl -u plugin_loader -n 30 --no-pager 2>/dev/null || true; res failed false; fi; [ -n "$TMP" ] && rm -rf "$TMP"; exit $rc' EXIT
# Symlink refusal: every component root will write under must be a real directory owned by $U.
G="$(id -gn "$U")"
[ -d "$H" ] && [ ! -L "$H" ] || { echo "home $H missing or a symlink"; exit 6; }
if [ -e "$HB" ]; then
  [ -d "$HB" ] && [ ! -L "$HB" ] && [ "$(stat -c %u "$HB")" = "$(id -u "$U")" ] || { echo "$HB is a symlink or not owned by $U — refusing"; exit 6; }
fi
if [ "$mode" = uninstall ]; then          # mirrors decky-installer cli/uninstall.sh + the daemon-reload it forgets; NO rm -rf /tmp/plugin_loader (user-controllable name, no product benefit)
  systemctl disable --now plugin_loader.service 2>/dev/null || true
  rm -f "$UNIT"; [ -d "$HB/services" ] && [ ! -L "$HB/services" ] && rm -rf "$HB/services"
  for d in "$H/.steam/steam" "$H/.local/share/Steam" "$H/.var/app/com.valvesoftware.Steam/data/Steam"; do
    [ -d "$d" ] && [ ! -L "$d" ] && runuser -u "$U" -- rm -f "$d/.cef-enable-remote-debugging" || true
  done
  systemctl daemon-reload; echo "removed; $HB/plugins and settings kept"; exit 0
fi
TMP="$(mktemp -d)"
# Resolve the stable tag WITHOUT the rate-limited API: one un-followed hop of releases/latest/download
# (observed 2026-09-06 from a Mac: 302 -> .../releases/download/v3.2.8/PluginLoader). Host+shape pinned.
LATEST="https://github.com/SteamDeckHomebrew/decky-loader/releases/latest/download/PluginLoader"
if ! NEXT="$("${CURL[@]}" -o /dev/null -w '%{redirect_url}' "$LATEST")"; then NEXT=""; fi   # a curl FAILURE (not just a mis-shape) also reaches the fallback
if [[ ! "$NEXT" =~ ^https://github\.com/SteamDeckHomebrew/decky-loader/releases/download/(v[0-9]+(\.[0-9]+){1,3})/PluginLoader$ ]]; then
  if ! API="$("${CURL[@]}" -L -H 'Accept: application/vnd.github+json' https://api.github.com/repos/SteamDeckHomebrew/decky-loader/releases/latest)"; then echo "tag resolution failed"; exit 4; fi
  NEXT="$(printf '%s' "$API" | python3 -c 'import json,sys;m=json.load(sys.stdin);print([a["browser_download_url"] for a in m["assets"] if a["name"]=="PluginLoader"][0])')" || { echo "unexpected release json"; exit 4; }
  [[ "$NEXT" =~ ^https://github\.com/SteamDeckHomebrew/decky-loader/releases/download/(v[0-9]+(\.[0-9]+){1,3})/PluginLoader$ ]] || { echo "unexpected asset url: $NEXT"; exit 4; }
fi
TAG="${BASH_REMATCH[1]}"
"${CURL[@]}" -L --max-filesize 209715200 -o "$TMP/PluginLoader" "$NEXT" || { echo "download failed"; exit 4; }
python3 -c 'import os,sys;p=sys.argv[1];sys.exit(0 if os.path.getsize(p)>=5000000 and open(p,"rb").read(4)==b"\x7fELF" else 1)' "$TMP/PluginLoader" || { echo "download is not a plausible PluginLoader"; exit 4; }
# Unit: the tag-pinned upstream file if its shape checks out, else the embedded v3.2.8 copy (byte-identical to main at design time).
if ! "${CURL[@]}" -L -o "$TMP/unit" "https://raw.githubusercontent.com/SteamDeckHomebrew/decky-loader/$TAG/dist/plugin_loader-release.service" \
   || ! grep -q '^ExecStart=\${HOMEBREW_FOLDER}/services/PluginLoader$' "$TMP/unit" || ! grep -q '^User=root$' "$TMP/unit"; then
  cat >"$TMP/unit" <<'U'
[Unit]
Description=SteamDeck Plugin Loader
After=network.target
[Service]
Type=simple
User=root
Restart=always
KillMode=process
TimeoutStopSec=15
ExecStart=${HOMEBREW_FOLDER}/services/PluginLoader
WorkingDirectory=${HOMEBREW_FOLDER}/services
Environment=UNPRIVILEGED_PATH=${HOMEBREW_FOLDER}
Environment=PRIVILEGED_PATH=${HOMEBREW_FOLDER}
Environment=LOG_LEVEL=INFO
[Install]
WantedBy=multi-user.target
U
fi
python3 - "$TMP/unit" "$TMP/unit.r" "$HB" <<'PY'
import sys; src,dst,hb=sys.argv[1:4]; open(dst,"w").write(open(src).read().replace("${HOMEBREW_FOLDER}",hb))
PY
printf '%s\n' "$TAG" >"$TMP/loader.version"
# Everything fetched and verified: now (and only now) touch the box. User-tree dirs are made AS THE USER (no chown ever).
runuser -u "$U" -- mkdir -p "$HB" "$HB/plugins" "$HB/settings"       # existing dirs untouched (Decky roots plugins/ itself)
systemctl disable --now plugin_loader 2>/dev/null || true
if [ -d "$HB/services" ]; then [ ! -L "$HB/services" ] || { echo "services/ is a symlink — refusing"; exit 6; }; PREV="$HB/services.prev.$$"; mv "$HB/services" "$PREV"; fi
install -d -m 0755 -o root -g root "$HB/services" "$HB/services/.systemd"   # ROOT-owned from here on: Decky only ever writes here as root
install -m 0755 -o root -g root "$TMP/PluginLoader" "$HB/services/PluginLoader"
install -m 0644 -o root -g root "$TMP/loader.version" "$HB/services/.loader.version"   # nothing in Decky reads it; world-readable for the agent
install -m 0644 -o root -g root "$TMP/unit.r" "$HB/services/.systemd/plugin_loader-release.service"
if command -v getenforce >/dev/null 2>&1 && [ "$(getenforce 2>/dev/null)" = Enforcing ]; then chcon -t bin_t "$HB/services/PluginLoader" || echo "chcon failed (will be caught by the liveness check)"; fi
install -m 0644 -o root -g root "$TMP/unit.r" "$UNIT"
for d in "$H/.steam/steam" "$H/.local/share/Steam" "$H/.var/app/com.valvesoftware.Steam/data/Steam"; do
  if [ -d "$d" ] && [ ! -L "$d" ]; then runuser -u "$U" -- touch "$d/.cef-enable-remote-debugging"; fi   # as the user: a planted symlink is followed only with the user's own rights
done
systemctl daemon-reload; systemctl enable --now plugin_loader
# Verify the thing the user needs, not the unit state: Restart=always makes is-active TRUE between crashes.
sleep 2
ok=0
for _ in $(seq 1 15); do
  if [ "$(systemctl show -p NRestarts --value plugin_loader)" = 0 ] && curl -fsS --max-time 2 -o /dev/null http://127.0.0.1:1337/auth/token; then ok=1; break; fi
  sleep 1
done
[ "$ok" = 1 ] || { echo "plugin_loader did not come up cleanly (NRestarts=$(systemctl show -p NRestarts --value plugin_loader))"; exit 5; }
[ -n "$PREV" ] && rm -rf "$PREV"; PREV=""
echo "installed $TAG"; exit 0
```

Hardenings upstream's `cli/install_release.sh` lacks: `set -euo pipefail`; baked user (upstream resolves `/homebrew` when `SUDO_USER` is unset); no `jq`, no `curl | sh`; `--proto/--proto-redir '=https'` (a redirect to `http://` is refused), `--connect-timeout/--max-time/--retry` on every fetch; tag+host pinned with a real fallback (a curl *failure* reaches the API branch, not only a mis-shape); ELF/size check; download and verify **before** touching `services/`, and `services/` is *moved aside* not deleted so any later failure (ENOSPC, `daemon-reload`, loader not coming up) **rolls back** to the previous loader and re-enables it; `services/` root-owned 0755 and written only with `install` (unlinks dest) — no `printf >`, `cp`, `touch` or `chown` as root under `$HOME`; user-tree dirs/flags created **as the user** via `runuser`; symlink refusal (exit 6) on `$H`, `$HB`, `services/` and each Steam dir; liveness = `NRestarts == 0` **and** `/auth/token` answering, not `is-active`; journal tail appended to the log on failure; kernel flock with a bounded wait; `refused` result under the lock; no `rm -rf /tmp/plugin_loader`; unit substitution via Python `str.replace` (no `sed` metacharacter trap); no quotes can enter the JSON (`TAG` is regex-pinned, `mode` enum). Exit codes: 2 usage, 3 (unused, reserved), 4 download/shape, 5 loader did not come up, 6 symlink/ownership refusal, 75 busy, 77 not opted in.

Residual, stated: `~/homebrew` itself must stay user-owned (plugins such as CSS Loader write there), so the desktop user can still rename `services/` under the loader between runs — that is the Decky-design fact in §1, not something this wrapper can close.

### 4.2 Unit template (heredoc, installed to `/etc/systemd/system/couchside-decky-loader@.service`, `daemon-reload`)

```
[Unit]
Description=Couchside: Decky Loader %i (phone-triggered, fixed procedure)
ConditionPathExists=/etc/couchside/allow-decky
[Service]
Type=oneshot
TimeoutStartSec=900
ExecStart=/etc/couchside/couchside-decky-loader %i
```
`%i` reaches only the wrapper's validator; both callers name the instance from the frozen `_DECKY_UNITS` dict. `ConditionPathExists` is a second, unit-level opt-in gate; because a condition-skipped start still exits 0, §4.5 never trusts `started` alone. `TimeoutStartSec=900` (oneshot's default is infinite): PID 1 SIGTERMs a hung run, the EXIT trap writes `failed` and rolls back, the flock dies with the process. No `[Install]` — never enabled, only started.

### 4.3 Helper verb (couchside-helper.py, VERSION 1.1.0)

```python
_DECKY_WRAPPER = "/etc/couchside/couchside-decky-loader"
_DECKY_MARKER = "/etc/couchside/allow-decky"
_DECKY_UNITS = {"install": "couchside-decky-loader@install.service",
                "uninstall": "couchside-decky-loader@uninstall.service"}

def verb_decky_loader(mode):
    """Start the pinned oneshot unit (detached, under PID 1). NOT a child of
    this helper: ProtectHome=yes would hide ~/homebrew from it, and a minutes-
```

### 4.5 Agent shim, request correlation, running flag

```python
_DECKY_VIA_HELPER = True     # emergency constant only; the runtime choice is _decky_helper_verb() below
_DECKY_REQ = {"mode": None, "requested_at": 0.0, "unit": None}   # module state, set on every start

def _decky_helper_verb():
    """'present' | 'outdated' | 'absent' | 'unreachable', cached 30 s. Probe = the verb with an
    argument its validator REJECTS ('probe'): a 1.1.0 helper answers 'invalid argument for
    decky.loader' (nothing spawned — validators run before handlers), a 1.0.0 helper answers
    'unknown verb'. No new verb, no spawn, no root work."""
    if not os.path.exists(HELPER_SOCKET):
        return "absent"
    r = _helper_call("decky.loader", "probe", timeout=5)
    if r is None:
        return "unreachable"          # socket present, no/garbled answer (helper busy or crashed)
    err = r.get("error", "")
    return "outdated" if err == "unknown verb" else "present"

def _decky_loader_start(mode):            # mode is a module literal chosen by the route
    if not (os.access(_DECKY_WRAPPER, os.X_OK) and os.path.exists(_DECKY_UNIT_TMPL)):
        return {"started": False, "needs_installer": True}
    if not os.path.exists(_DECKY_MARKER):
        return {"started": False, "needs_optin": True}
    if _decky_busy():
        return {"started": False, "busy": True, "what": _decky_busy()}
    unit = _DECKY_UNITS[mode]
    hv = _decky_helper_verb() if _DECKY_VIA_HELPER else "absent"
    if hv == "outdated":
        return {"started": False, "helper_outdated": True}       # final; the sudo grant is NOT tried (rule 3)
    if hv == "unreachable":
        return {"started": False, "helper_unreachable": True, "retry": True}
    _DECKY_REQ.update(mode=mode, requested_at=time.time(), unit=unit)
    if hv == "present":
        r = _helper_call("decky.loader", mode, timeout=20)
        if r is None:
            return {"started": False, "helper_unreachable": True, "retry": True}
        if not r.get("ok"):
            return {"started": False, "via": "helper", "detail": r.get("error") or r.get("detail", "")}
        return _decky_confirm_started(unit, via="helper")
    if not _sudo_nopasswd_allows(unit):
        return {"started": False, "needs_optin": True}
    r = subprocess.run(["sudo", "-n", "/usr/bin/systemctl", "start", "--no-block", unit],
                       capture_output=True, text=True, timeout=15)
    if r.returncode != 0:
        return {"started": False, "via": "sudo", "exit_code": r.returncode, "detail": (r.stderr or "").strip()[:200]}
    return _decky_confirm_started(unit, via="sudo")

def _decky_confirm_started(unit, via):
    """`systemctl start --no-block` returns 0 for a condition-skipped unit and before the
    wrapper runs. Wait <=3 s for the lock to be held or ActiveState=activating; else read
    ConditionResult/Result/ExecMainStatus and answer honestly."""
    deadline = time.monotonic() + 3.0
    while time.monotonic() < deadline:
        if _decky_op_running() or _unit_prop(unit, "ActiveState") in ("activating", "active"):
            return {"started": True, "via": via, "log": _DECKY_RUN + "/decky-loader.log"}
        time.sleep(0.2)
    cond, res, st = _unit_prop(unit, "ConditionResult"), _unit_prop(unit, "Result"), _unit_prop(unit, "ExecMainStatus")
    if cond == "no" or st == "77":
        return {"started": False, "needs_optin": True}
    if st == "75":
        return {"started": False, "busy": True}
    return {"started": False, "did_not_start": True, "detail": "unit %s result=%s status=%s" % (unit, res, st)}
```
Rules pinned by `tests/test_helper_shim.py` still hold and gain two cases: (a) a helper *refusal* (incl. `unknown verb`) is final — no sudo; (b) socket present but silent/garbled (`_helper_call` :7383 returns `None` on any `OSError`/`ValueError`, including a recv timeout) is **not** "absent": it returns `helper_unreachable` instead of falling through to a sudo path that, on a helper-only box, would wrongly tell the owner to run `allow-decky on`. Only a missing socket file takes the sudo path. The helper's refusal key is `error` (dispatch :376-389), so `detail` surfaces `r.get("error") or r.get("detail")`.

**Correlation** (the stale-result hole): `_decky_loader_state()` reports `op` from three sources — the flock, `decky-loader.result` (root 0644, atomic), and `_DECKY_REQ`. `op.state` is `starting` while `requested_at` is set and no result with `at >= floor(requested_at) - 1` exists and the lock is free; after 20 s in `starting`, `systemctl show -p Result,ExecMainStatus,ConditionResult,ActiveState --value <unit>` decides: `ConditionResult=no`/77 → `did_not_start` + `needs_optin`; 75 → `busy`; else `did_not_start` with the unit's `Result=`. Lock free **and** result `running` → `interrupted, ok:false` (SIGKILL/OOM: the trap never ran). Lock held → `running`. A fresh `done`/`failed`/`refused` with `at` ≥ the request → the verdict. A result older than the request is never shown as this request's outcome. `_decky_op_running()` opens `_DECKY_RUN/decky-loader.lock` read-only and tries `fcntl.flock(fd, LOCK_SH | LOCK_NB)`; `BlockingIOError` = running; absent = idle; the shared lock is released immediately (the wrapper's `flock -w 15` absorbs the overlap either way). `decky-loader.log` (constant path) is the transcript.

## 5. Opt-in / trust decision

New switch `couchside allow-decky on|off|status` (CLI case cloned from `allow-system-updates`, install.sh :1889-1941, with the `/dev/tty` read factored into a `confirm_tty()` shell function so `tests/test_decky_optin.sh` can stub the *function* after `eval` — the `sudo() { "$@"; }` precedent — instead of rewriting shipped text). `on`: requires `-x $DECKY_WRAP` and `-f $DECKY_UNIT_TMPL` else "re-run install.sh first"; prints exactly what it grants, in this order and wording (the material fact first): *"Decky Loader runs as root from your home directory. On a Decky box, anyone who can act as your desktop user — including a paired phone, through the gamepad — can become root. That is Decky's design, not something Couchside can wall off."* Then: that the phone (any token holder) can install/repair/remove Decky Loader as a root service downloaded from GitHub over TLS with **no upstream checksum**, and install curated store plugins that Decky sha256-checks but which run as your user or, if flagged, **as root**. `y/N` via `confirm_tty`; `visudo -cf`; installs `zz-couchside-decky` 0440 and the marker `/etc/couchside/allow-decky` (root 0644). `off` removes both. `n` at the install-time offer writes `/etc/couchside/decky-optin-declined` (root 0644) so the offer is not repeated on every re-run; `allow-decky on` removes the stamp.

Route gating rule (replaces "read-only vs mutating"): **any route that opens the Decky WebSocket or leaves the LAN on demand requires the marker; pure filesystem/cache reads are token-only.** Every route is listed under one of the two in §6.

Why not reuse `allow-system-updates`: README :161 promises it "cannot install new software". Why not unconditional: agent self-update is opt-in although Ed25519-signed; launcher creation is opt-in because it is arbitrary exec; this is strictly more than both. "Directly from the app" is honoured by install.sh **offering** the opt-in in an interactive run (`ask_yn "Let the app install and manage Decky Loader and its plugins?"` :266 already reads `/dev/tty` and defaults to no), shown only when a Steam root exists and neither the marker nor the declined stamp exists — so a fresh box needs no second terminal trip, no env var or flag can enable it non-interactively, and the detached app-driven update (`update_apply` :2083, no tty) safely defaults to no. The `DeckyCard` shows the one-line hint `couchside allow-decky on` whenever `installer_ready && !allowed`, loader installed or not, so the feature is discoverable from the phone the owner actually uses.

## 10. Plugin install / update / uninstall / reload

Precondition chain `_decky_ready_for_ops()`: marker → 403; `_decky_busy()` (flock **or** job slot **or** a `check` in flight) → 409 `{busy, what}`; state `installed_stopped` → **409 `{error:"loader_stopped", restart_action:"restart-decky"|null, repair:true, stopped_reason}`** — no auto-restart: restarting the loader restarts every plugin (KI-037), and a loader that stopped itself over a Steam crash loop would stop again mid-extract; the app offers the existing Restart Decky action with the KI-037 wording and retries; `running_untrusted`/`running_unreachable` → 503 `loader_down, repair:true`; job slot taken under `_DECKY_JOB_LOCK` and the record written to `_DECKY_JOB_FILE` atomically **before** any socket.

`_DeckyWS` (~110 lines, its **own** framing — `_WebOSWS.recv_text` :12078 has no frame-length cap and its timeout is per `recv()`, so a user-level impostor on a free port 1337 could pin the job thread forever): masked client frames, handshake accept check, **frame length > 1 MiB → close + raise**, one overall deadline per `call` (`settimeout(remaining)` recomputed before every recv), events collected ≤64 per call, ping/pong ignored, close frame on exit. Opened on `ws://127.0.0.1:1337/ws?auth=<token>` only after `_decky_loader_is_root()` and `GET /auth/token` (shape-validated; re-fetched per session, it rotates on loader restart); ids from `SystemRandom().randrange(2**40, 2**52)`; `call(route, *args, timeout)` refuses routes outside `_DECKY_WS_ROUTES = frozenset({"utilities/ping", "loader/get_plugins", "loader/reload_plugin", "utilities/install_plugin", "utilities/confirm_plugin_install", "utilities/cancel_plugin_install", "utilities/uninstall_plugin", "updater/get_version_info"})`, sends `{"type":0,"route","args","id"}`, reads until its id (type 1/-1/2), acks `{"type":3,"id"}`, collects type-5 events. **Every socket session has a hard total budget of 3 s** (the displaced Steam frontend reconnects at ~5 s and closes us); every job thread runs under a watchdog (install 150 s, uninstall 40 s, reload 20 s) that marks the job `failed` and frees the slot.

Install/update job: resolve store entry + installed version → `install_type` = INSTALL(0)/UPDATE(2)/DOWNGRADE(3)/REINSTALL(1) by `_semver_tuple` comparison (unparsable installed version → REINSTALL, presented as such) → one write burst under the 3 s budget: `utilities/install_plugin(artifact, name, version, hash, install_type)` (hash always non-empty so Decky's `SHA-256 Mismatch` gate runs) → read the `loader/add_plugin_install_prompt` event whose name+version match, take its `request_id` → `utilities/confirm_plugin_install(request_id)` → **close** (calls run as tasks, verified, so the install proceeds server-side). Budget exceeded before the prompt → `retry` (not `failed`) and, if a `request_id` is known, `utilities/cancel_plugin_install` in a fresh ≤1 s session; socket closed after `install_plugin` returned but before the confirm reply → outcome `unknown`, read-back continues. Read-back: poll the fs ≤120 s for a folder whose `plugin.json.name == name` and `package.json.version == version`; **folder presence is necessary, not sufficient** (Decky returns without importing when a `remote_binary` fetch fails — files stay on disk, verified with the Dummy C case): once the folder appears, one `loader/get_plugins` (≤1 s hold) must list the name with `disabled:false`, else `failed` with `error:"extracted but not loaded"` and `log` = last 30 lines of `journalctl -u plugin_loader.service` via the existing `logs.journal` verb / journal wrapper. **Update failure after removal**: Decky's `_install` uninstalls the old copy *before* the sha256/extract step, so a failed update leaves no copy; on any failed UPDATE the agent re-scans and, if the folder is absent, sets `error:"update failed; <name> <old_version> was removed by Decky Loader — reinstall from the Store"` and `reinstall_id:<store id>` so the app offers one-tap **Reinstall**. Decky does the download, hash check, `extractall` (stdlib strips traversal), chown/chmod, backend start — Couchside never touches the bytes.

Uninstall job: `utilities/uninstall_plugin(name)` sent, reply awaited only within the 3 s budget (Decky's stop can take 1 s socket timeout + 5 s SIGKILL grace, plugin.py:147-191) → close → verify folder gone ≤15 s → `verified:true`; a mid-call close is `unknown` until the fs poll answers; `loader_down` is reserved for `/auth/token` failing. Reload job: `loader/reload_plugin(name)` — one backend restarted (KI-037's preferred granularity), `verified:null` (queued), outcome `done` once the reply arrives, `unknown` on close.

Persistence and resume: the job record (`kind,name,version,hash,store_id,started_at,phase,old_version`) lives in `_DECKY_JOB_FILE`; on agent start a record younger than 180 s resumes the fs + `get_plugins` read-back and finishes it; older → `outcome:"interrupted"`. `GET /api/decky/jobs` reads the record.

Frontend hand-off (honest limitation, KI-068): our connect displaces the Steam frontend; events emitted while we hold the socket, or while nobody does, are dropped; if the frontend reconnects between `install_plugin` and the prompt event, Decky's confirm modal appears **on the TV** instead, and an unacked reply may sit in `pending_responses` — behaviour on the frontend's FULL_SYNC unverified. So: the app copy on a prompt timeout says "Decky may be asking on the TV"; every op reply carries `steam_ui_up`; when true the app warns *before* an install/uninstall that "Decky's menu will blink and any open Decky prompt is cancelled" and afterwards offers **Reload Decky** (the existing `restart-decky` action; user-invoked, restarts all plugins) or says "appears next time Steam starts". Why no root-side extractor fallback: a loader that cannot be restarted cannot load what a root extractor places; the honest fallback is Repair (§11), then the API.

## 11. Decky Loader install / update / repair / uninstall

`op=install` is install, repair **and update** in one idempotent procedure (§4.1: keeps `plugins/`+`settings/`, stages the new `services/` beside the old, rewrites and re-pins the unit, restarts, verifies liveness, rolls back on any failure). **Loader update goes through Repair only.** `updater/do_update` is not exposed: it re-downloads the unit from decky-loader *main* (unpinned) and overwrites `/etc/systemd/system/plugin_loader.service`, `chmod 777`s the binary, returns before the 27 MB download finishes, follows the box's `branch` (a user who once picked Pre-release/Testing in Decky's settings would get a prerelease or open-PR CI build installed as root), and has no read-back — every one of those is a guarantee this spec makes and that route would revoke. Decky's own UI still offers its updater to users who want it; when they use it, `unit_pinned:false` shows up and Repair is offered. `POST /api/decky/loader/check` stays (read-only version info; the WS hold is bounded and marker-gated) and reports `channel` next to `remote`; the app's copy says "Repair installs the latest **stable** loader" whenever `channel != 0`. `op=uninstall` mirrors upstream (plugins/settings kept; copy says so). After a fresh install Steam must restart to honour `.cef-enable-remote-debugging`: state `installed_steam_needs_restart` (three-way detector, §7) drives the copy "Installed. Restart Steam or reboot to see the Decky menu" (existing `reboot` action offered); `running_no_steam` says nothing actionable; `installed_cef_flag_missing` offers Repair. On a Decky-owned box the agent survives an uninstall (it runs under `couchside.service`, which the plugin only enabled); `panel:"missing"` after a phone-side install says "re-run the Couchside installer to add the Couchside panel". Non-interactive by construction: root via PID 1, user baked, stdin none.

DECISIONS:
Root surface = ONE 2-mode bash heredoc wrapper (install|uninstall) run only via a pinned systemd oneshot template unit; no root-side zip extractor, no signed Python asset — Decky Loader already downloads, sha256-checks, extracts and chowns plugins itself (verified end-to-end at v3.2.8), so a second root extractor adds review surface without capability.
Root never follows a path under the user's home: user-tree directories and the CEF flag are created AS THE USER via runuser, `services/` is root-owned and written only with install(1), symlinked components abort (exit 6), nothing under $HOME is ever chown'ed to the user — the skeptic's `ln -sf /etc/shadow ~/.steam/steam/.cef-enable-remote-debugging` escalation is closed by construction, and the residual (the user can rename `services/` under the loader because `~/homebrew` must stay user-owned) is Decky's design, stated in §1 and the opt-in copy.
The opt-in copy, the Install alert and README lead with the material fact — Decky Loader runs as root from your home and makes the desktop user root-equivalent on that box — rather than with the checksum detail; KI-070 records that the helper's user≠root guarantee is void on Decky boxes and F9 considers gating the standing restart grant.
Loader self-update through Decky's `updater/do_update` is NOT exposed: it unpins the unit (re-fetched from main), chmod-777s the binary, follows the box's prerelease/testing branch, returns before the download and has no read-back; Repair (the wrapper) is the one update path, re-pins the unit every time, verifies NRestarts==0 + /auth/token, and rolls back on failure. `check` stays read-only and reports the channel.
Both privilege paths start the SAME unit (`systemctl start --no-block couchside-decky-loader@<mode>.service`): the helper verb because its service has ProtectHome=yes/PrivateTmp=yes and Accept=no; the sudoers grant on the exact systemctl argv so the wrapper itself carries no grant. `started` is never trusted from the start's exit code alone: `_decky_confirm_started` waits for the lock or `activating`, else reads `ConditionResult`/`ExecMainStatus` and answers `needs_optin`/`busy`/`did_not_start`.
Op results are correlated to the request (`requested_at` vs the result's `at`, `starting` until a fresh result or the lock appears, `interrupted` for lock-free+running, `refused` written by the wrapper under the lock) so a previous run's `done` can never render as this run's outcome; the wrapper takes the flock with a bounded wait so the agent's shared-lock probe cannot make it exit 75.
Every curl in the wrapper is bounded (`--proto '=https' --proto-redir '=https' --connect-timeout 20 --max-time 300 --retry 2`) and the unit has `TimeoutStartSec=900`, so a stalled transfer cannot hold the lock forever; a curl FAILURE (not only a mis-shaped redirect) reaches the API fallback; `services/` is moved aside, not deleted, and restored by the EXIT trap on any later failure.
The helper→sudo choice is runtime-detectable without a new verb: `decky.loader` is probed with an argument its validator rejects (`"probe"` → 1.1.0 answers "invalid argument", 1.0.0 answers "unknown verb", nothing spawns either way); `outdated` and `unreachable` are distinct terminal answers with their own copy, `unknown verb` is never carved out into a sudo retry, and only a MISSING socket takes the sudo path (a present-but-silent socket is not "absent"). `_DECKY_VIA_HELPER` remains as an emergency constant only.
A stopped loader is never restarted silently inside a plugin op (KI-037: every plugin restarts; a self-stopped loader in a Steam crash loop would stop again mid-extract): plugin ops answer 409 `loader_stopped` naming the existing Restart Decky action, and `stopped_reason` tells the user when Decky stopped itself.
`_DeckyWS` is its own bounded client (1 MiB frame cap, one deadline per call, event cap, 3 s per socket session, per-job watchdogs) because `_WebOSWS` has no length cap and a user-level impostor on a free port 1337 could pin the job slot or OOM the agent; the loader's identity is checked via `/proc/net/tcp` (listener uid 0) before any token is fetched, and a non-root listener is `running_untrusted`, not "reachable".
Completion is read back from disk AND from one short `loader/get_plugins` (folder presence is necessary, not sufficient: Decky leaves files on disk when a remote_binary fetch fails); mid-call socket closes are `unknown`, never `failed`/`loader_down`; uninstall/reload are jobs like install so the app's 4 s request timeout never turns a completed op into a reported failure; the job record is persisted and resumed across agent restarts; a failed update that removed the old copy says so and offers one-tap Reinstall.
Plugin listing is filesystem-only with resolved-vs-resolved containment (symlinked homebrew, /var/home), 64 KiB read caps, `loader.json` parse failure → flags unknown (never "enabled"), strict semver (no phantom updates from `-pre`/hash suffixes), and `running` withheld (`null`) until a VERBATIM /proc fixture exists — a Phase B precondition, not a promise.
Client surface for install is a single store `id` (int-not-bool, bounded; path segment `[0-9]{1,9}`), looked up in the box's own cache; versions[0] is always used, its hash must be 64-hex (else 422), the artifact URL is agent-built, install_type is agent-computed and presented (Install/Update/Reinstall/Downgrade with explicit confirms), `Couchside` (NFKC-normalised) is protected on every op INCLUDING the store entry's name so the phone cannot replace its own management surface.
Store list and icons are fetched box-side through a no-redirect opener with host+scheme pins checked on the URL that is actually fetched, every served field is type-checked and capped by rejection (a 3 MiB `tags` array cannot reach the phone), fetches run in a background thread (never inside a GET), AVIF is sniffed so `has_icon` never advertises a 404. Phone→CDN was rejected: README promises the app 'never talks to anything except your service'.
One `_decky_busy()` mutex covers the wrapper flock, the plugin job slot and an in-flight `check`, so a Repair cannot `rm`/move `services/` while Decky is mid-extract and a plugin op cannot connect to a loader mid-swap.
Route gating is stated per route: anything that opens the Decky WebSocket or leaves the LAN on demand needs the marker; filesystem/cache reads are token-only (icons are served from cache without the marker but fetched only with it).
`GET /api/decky/loader` is memoised and cached (30 s for grant/marker/helper facts, 10 s for the :8080 probe at 0.5 s, 2 s for unit/token facts) so the 2 s poll never stacks `sudo -l` spawns or blocks 1.5 s per request; the Steam detector is three-way (no Steam / flag missing / needs restart) with a flag-mtime-vs-process-start rule, so it never issues "Restart Steam" when Steam is simply closed.
No new cap (404-probe on /api/decky/loader; `utilities` cap already exists at all six sites); `decky` is a real runnable Utilities tenant emitted only on Steam boxes (no client ever sees `unsupported`), a missing `?op=` from an old app gets a human string not a 400, the Actions-tab mount stays OpenPuck-only, and the Setup card is not pref-gated because the box-side opt-in is the consent; in Phase A the card derives solely from `/api/decky/loader`.
`_decky_loader_installed()` (bool) and `_decky_plugins_on_disk()` (dict) are two names for two contracts so the membership gate between the phone's `name` and the WS call cannot be 'fixed' away; `installed_by` replaces `owns_agent`, which could never be false when the panel existed.
One new opt-in `couchside allow-decky` (never reuse allow-system-updates, whose README promise is 'cannot install new software'), prompted through a stub-able `confirm_tty` on /dev/tty, offered once by an interactive install.sh run (skipped when the marker or a declined stamp exists), discoverable from the DeckyCard hint; no env var or flag enables it non-interactively. Marker-gating the helper's existing `update.*` verbs is dropped from this PR (F8) — it coupled to a file phase 2 plans to remove and widened an already large PR.
Phased: Phase 0 (pull, bump to 2.9.105/1.1.0/2.9.58, CHANGELOG), Phase A (loader install/repair/uninstall + opt-in + framework) independently shippable with its own 401/403/zero-spawn tests, Phase B (plugins/store) gated on A's hardware checks and the /proc fixture; enable/disable, version pick, update-all, in-CEF hand-off, vendoring into couchside-decky, prerelease channel, auto-panel-install, update-verb markers and the restart-grant gate are explicit follow-ups.
